流水车间调度（Flow Shop Scheduling）描述的是这样一类问题：有若干件工件要依次经过同一组机器，每台机器同一时刻只能加工一件工件。怎样安排工件的先后顺序，才能让所有工件尽早完成？

它看起来像排队问题，实质上却是运筹学中很典型的组合优化问题。工件顺序一旦改变，机器等待和工件等待都会随之改变。

## 先把问题说清楚

设有 n 件工件、m 台机器。第 j 件工件在第 k 台机器上的加工时间记为 p_jk。在最常见的流水车间模型中：

- 每件工件都按相同的机器顺序加工，例如 M1 → M2 → … → Mm；
- 一台机器同一时间只能处理一件工件；
- 一件工件在前一道工序完成前，不能进入下一台机器；
- 通常假设加工过程不被中断。

如果所有机器上的工件顺序一致，这种安排叫作**排列流水车间调度**（permutation flow shop）。它是实践中最常见、也最便于分析的一类。

我们的目标通常是最小化最大完工时间：

**Cmax = max_j Cjm**

其中 Cjm 表示工件 j 在最后一台机器上完成的时刻。直观地说，Cmax 就是整批订单全部完成所需的时间，也常被称为工期或 makespan。

## 一个小例子

考虑三件工件 A、B、C，它们依次经过两台机器。加工时间如下：

| 工件 | 机器 M1 | 机器 M2 |
| --- | ---: | ---: |
| A | 3 | 6 |
| B | 7 | 2 |
| C | 4 | 5 |

若按 A → B → C 加工，第一台机器的完成时刻为 3、10、14。第二台机器要同时等待“工件已从 M1 完成”和“机器 M2 空闲”两个条件，因此完成时刻依次为：

~~~text
C_A,2 = max(3, 0) + 6 = 9
C_B,2 = max(10, 9) + 2 = 12
C_C,2 = max(14, 12) + 5 = 19
~~~

所以该顺序的 Cmax = 19。计算中不断出现的 `max`，正是流水车间里“机器不能抢跑”的约束。

## 两台机器时：Johnson 法则

当只有两台机器，并且目标是最小化 Cmax 时，Johnson 法则可以给出最优顺序。

它的做法很直观：在所有尚未安排的加工时间中，找到最小值。

- 如果最小值出现在第一台机器上，就把对应工件尽量安排在前面；
- 如果最小值出现在第二台机器上，就把对应工件尽量安排在后面；
- 删除该工件后继续，直到所有工件都被安排完。

它背后的想法是：第一台机器加工很快的工件应尽早放行，第二台机器加工很快的工件则应尽量靠后，减少最后阶段的等待。

下面是一个简洁的 Python 实现。输入格式为 `{工件名: (M1加工时间, M2加工时间)}`：

```python
def johnson_order(processing_times):
    remaining = dict(processing_times)
    front, back = [], []

    while remaining:
        job, (time_m1, time_m2) = min(
            remaining.items(),
            key=lambda item: min(item[1]),
        )

        if time_m1 <= time_m2:
            front.append(job)
        else:
            back.append(job)

        del remaining[job]

    return front + back[::-1]


jobs = {
    "A": (3, 6),
    "B": (7, 2),
    "C": (4, 5),
}

print(johnson_order(jobs))  # ['A', 'C', 'B']
```

对于上面的例子，Johnson 法则得到 A → C → B。其最大完工时间为 16，比原先顺序少 3 个时间单位。这个差距在工件更多、时间差异更大时会更加明显。

## 多台机器时，难点在哪里？

当机器数量增加到三台及以上时，问题会迅速变复杂。对于一般的排列流水车间问题 F_m || Cmax，已经很难用一个像 Johnson 法则这样简单的规则总能得到最优解。

常见做法是使用启发式算法，在较短时间内找到质量较高的顺序。其中很常用的是 **NEH 启发式**：

1. 按每件工件在所有机器上的总加工时间从大到小排序；
2. 先取前两件工件，选择较好的排列；
3. 依次加入下一件工件，尝试插入当前序列的每一个位置；
4. 保留能使 Cmax 最小的位置。

NEH 不保证在所有实例上都最优，但在很多基准问题和实际场景中表现很稳定。它也说明了一个很重要的思路：先处理对整体工期影响最大的工件，再通过局部插入不断修正顺序。

## 如何计算一个给定顺序的工期？

无论使用什么优化方法，都需要一个可靠的评价函数。下面的函数根据工件顺序和加工时间矩阵，计算最大完工时间：

```python
def makespan(order, processing_times):
    # processing_times[job] = [p_j1, p_j2, ..., p_jm]
    machine_ready = [0] * len(processing_times[order[0]])

    for job in order:
        previous_operation = 0
        for machine, duration in enumerate(processing_times[job]):
            start = max(machine_ready[machine], previous_operation)
            finish = start + duration
            machine_ready[machine] = finish
            previous_operation = finish

    return machine_ready[-1]


times = {
    "A": [3, 6],
    "B": [7, 2],
    "C": [4, 5],
}

print(makespan(["A", "C", "B"], times))  # 16
```

这里 `machine_ready[machine]` 记录每台机器何时空闲，`previous_operation` 记录当前工件的上一道工序何时完成。两者取最大值，就是当前工序真正能开始的时间。

## 还可以加入哪些现实约束？

基础模型很干净，现实问题往往更丰富，例如：

- 机器切换不同产品时需要准备时间；
- 工件有交期，需要考虑延期；
- 某些工件优先级更高；
- 中间缓冲区容量有限；
- 机器可能故障，或某些工序可由多台设备完成。

这些约束会改变目标函数和可行解空间，也会让精确求解更困难。此时可以结合整数规划、分支定界、局部搜索、遗传算法或强化学习等方法；但无论算法多复杂，先清楚地写出工件、机器、工序顺序和评价指标，始终是建模的第一步。

## 小结

流水车间调度的核心不是“给任务排个队”，而是在机器能力有限、工序有先后依赖的条件下，减少整个系统的等待。两台机器时可以从 Johnson 法则入手；机器增多后，可以尝试 NEH 这样的启发式方法。理解完工时间的递推关系，再去看更复杂的调度算法，会容易得多。
